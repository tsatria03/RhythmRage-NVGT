Post-reorg, RhythmRage splits **source** (`src/`: `rg.nvgt`, `lt.nvgt`, `lt.properties`, `includes/`) from the **game data/run folder** (`rg/`: `packs/`, `mypacks/`, `sounds/`, `sounds1.pack`, `sounds2.pack`, `docks/`, `parser.md`, and the launchers). Runtime/compiler + auto_chdir facts: [[nvgt-engine-location]]; miniaudio/libs: [[nvgt-090-miniaudio-not-bass]].

**Running from source.** Launchers `rg/rg.py` and `rg/lt.py` run `C:\nvgt2\nvgt2.exe` on `..\src\rg.nvgt` / `..\src\lt.nvgt` (full-featured launchers: hide their own console, capture compile output to `errors.txt`/`lt_errors.txt`, watch ~5s then detach on a clean start). NVGT's auto_chdir sets the working directory to the **script's folder (`src/`)** from source, so the game reaches its data (in the sibling `rg/`) via a `path="../rg/"` prefix: `rg.nvgt` main() has `if (!installed and !SCRIPT_COMPILED) path="../rg/";` (installed → `%APPDATA%/Oriol Gomez/rg/`; compiled → `path=""`). `generate_soundpack()` reads `path+"sounds/*"`. `lt.nvgt` scans `SCRIPT_COMPILED?"mypacks":"../rg/mypacks"`. Save is always `%APPDATA%\Oriol Gomez\rg\saves\rg.dat` (absolute, in ser()/deser()); sound packs are `path+"sounds"+lang+".pack"` (nopack() in includes/utils.nvgt).

**Compiled layout.** `C:\nvgt2\config.properties` sets bundling on (windows=folder, mac=.app) and there is NO project `rg.properties`, so `nvgt2 -pwindows -c rg.nvgt` → `src/rg/` (rg.exe + lib) and `-pmac` → `src/rg.app` (`Contents/MacOS/rg` stub + `Contents/Frameworks/libphonon.dylib` + `Contents/Resources/exec` = the game bytecode/payload). Compiled `path=""` works because auto_chdir → the exe's dir (Windows: the folder; a bundled Mac .app → `Contents/Resources`). The `#pragma asset` lines were removed, so the bundler copies NO game data — build/tools.py copies it in.

**build/tools.py** (run via `build/tools.bat`) is a menu: git helpers (commit/undo/push/history/tag) + **Compile (Windows+Mac)** + **Package (Windows+Mac zip)**. The **website layer was removed entirely** (no site to host on). The rest of the inherited release pipeline (`run_release`, versioning, GitHub release) is present but **crossed out** — menu options hidden, config constants + the CLI arg path guarded — kept for later, never runs. Compiler hardcoded to `C:\nvgt2\nvgt2.exe` (the shared `~/.game_tools/tools.ini` `nvgt` key is the legacy engine and would be wrong here).
- **Compile**: ship-list copied from `rg/` = `docks`, `packs`, `parser.md`, `sounds1.pack`, `sounds2.pack` (NOT `mypacks/`, raw `sounds/`, launchers, or lib) — placed next to `rg.exe` on Windows, into `Contents/Resources` on Mac. Windows also compiles `lt.nvgt` → bare `lt.exe` (lt.properties bundling off) dropped beside `rg.exe` (shares that folder's `lib/`) plus an **empty `mypacks/`** so authors have a workspace — this ships the level tool with the game, BGT-style. **Level tool is Windows-only for now** (its `run()`/`input_box` are Windows-oriented; a Mac tool would need a separate `lt.app` + a Mac run-level fix). Cleans stale `src/rg`/`src/rg.app` first (nvgt -c fails if a dir named after the script sits beside it; both are gitignored). Output → `releases/windows/RhythmRage_windows/rg/` and `releases/mac/RhythmRage_mac/rg.app`.
- **Package** → `releases/archives/`: Windows via `shutil.make_archive` (archive root = `rg/`). Mac via a hand-built `zipfile` that stamps **0755 on `rg.app/Contents/MacOS/rg`** (0644 elsewhere) so the cross-built app keeps its Unix exec bit — a naive Windows zip strips it and the `.app` won't launch. Extract → `rg/` (Windows) / `rg.app` (Mac).
