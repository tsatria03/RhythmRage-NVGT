Post-reorg, RhythmRage splits **source** (`src/`: `rg.nvgt`, `lt.nvgt`, `lt.properties`, `includes/`) from the **game data/run folder** (`rg/`). All runtime game data lives under **`rg/data/`**: `assets/` (built voice/UI sound packs `sounds1.pack`/`sounds2.pack`), `packs/` (compiled rhythm packs + any loose author folder for creator mode), `saves/` (`rg.dat`). Also in `rg/`: `mypacks/` (loose author sources), `sounds/` (raw source built into `data/assets/`), `docks/` (`english/`+`spanish/`), and the launchers `rg.py`/`lt.py`. Runtime/compiler + auto_chdir facts: [[nvgt-engine-location]]; miniaudio/libs: [[nvgt-090-miniaudio-not-bass]].

**Source is modular (not one monolith):** `rg.nvgt` is now just the entry point — globals, `main()`, and the menu callbacks (`checkmenu`/`menu2`) — and pulls in the local includes via the wildcard `#include"includes/*.nvgt"`. Gameplay lives in `includes/game.nvgt` (`startlev`/`loadlev` parser, rhythm loop, store/change-pack/downloader browsers + first-letter helpers `next_first_letter`/`preview_pack`); the main menu + level select in `includes/menu.nvgt` (`start`/`startgame`); pack/sound-pack building in `includes/packgen.nvgt`. Plus the shared libs `classes.nvgt`, `enhanced_menu.nvgt`, `history.nvgt`, `reader.nvgt`, `number_speaker.nvgt`, `downloader.nvgt`, `utils.nvgt`. `lt.nvgt` uses **targeted** includes (not the wildcard). NVGT's builder de-dupes includes by absolute path, so a file pulled by both the wildcard and an explicit `#include` compiles once. When searching for a function, grep `src/` — it may be in any of these.

**Running from source.** Launchers `rg/rg.py` and `rg/lt.py` run `C:\nvgt2\nvgt2.exe` on `..\src\rg.nvgt` / `..\src\lt.nvgt` (full-featured launchers: hide their own console, capture compile output to `errors.txt`/`lt_errors.txt`, watch ~5s then detach on a clean start). NVGT's auto_chdir sets the working directory to the **script's folder (`src/`)** from source, so the game reaches its data (in the sibling `rg/`) via a `path="../rg/"` prefix: `rg.nvgt` main() has `if (!installed and !SCRIPT_COMPILED) path="../rg/";` (installed → `%APPDATA%/Oriol Gomez/rg/`; compiled → `path=""`). `generate_soundpack()` reads the raw source `path+"sounds/*"` and builds `path+"data/assets/sounds"+lang+".pack"`. `lt.nvgt` scans `SCRIPT_COMPILED?"mypacks":"../rg/mypacks"`. Save is the **portable** `path+"data/saves/rg.dat"` (in ser()/deser(), created via `directory_create(path+"data/saves")` in main() — moves with the game folder); sound packs load from `path+"data/assets/sounds"+lang+".pack"` (nopack() in includes/utils.nvgt); compiled rhythm packs from `path+"data/packs/"` (yespack()/checkpack()/generate_packs()). main() also creates `data/`, `data/assets`, `data/packs`.

**Compiled layout.** `C:\nvgt2\config.properties` sets bundling on (windows=folder, mac=.app) and there is NO project `rg.properties`, so `nvgt2 -pwindows -c rg.nvgt` → `src/rg/` (rg.exe + lib) and `-pmac` → `src/rg.app` (`Contents/MacOS/rg` stub + `Contents/Frameworks/libphonon.dylib` + `Contents/Resources/exec` = the game bytecode/payload). Compiled `path=""` works because auto_chdir → the exe's dir (Windows: the folder; a bundled Mac .app → `Contents/Resources`). The `#pragma asset` lines were removed, so the bundler copies NO game data — build/tools.py copies it in.

**build/tools.py** (run via `build/tools.bat`) is a menu: git helpers (commit/undo/push/history/tag) + **Compile (Windows+Mac)** + **Package (Windows+Mac zip)** + **Generate pack index** (scans `rg/data/packs/*.pack`, writes `rg/pack_index.txt` for the in-game downloader). The **website layer was removed entirely** (no site to host on). **Release** is a real menu action again: `do_release()` reads the version from `build/version.txt` (only tools.py reads it — the game never does), derives **tag `V{version}0`** (1.1 → `V1.10`) and **release title `{GAME} V{version}`** (`RhythmRage V1.1`, from tools.ini `name`), and `gh release create`s with `releases/archives/RhythmRage_windows.zip` + `RhythmRage_mac.zip` attached (overwrite-guard + confirm first). `do_full_release()` chains Compile → Package → Release. The old template `run_release()`/`sync_version_file()` are dormant dead code (superseded; no version.nvgt sync — the game carries no version). Compiler + `gh`/`sevenzip` tool paths still come from `~/.game_tools/tools.ini` except the NVGT compiler, hardcoded to `C:\nvgt2\nvgt2.exe`. Compiler hardcoded to `C:\nvgt2\nvgt2.exe` (the shared `~/.game_tools/tools.ini` `nvgt` key is the legacy engine and would be wrong here).
- **Compile**: ship-list copied from `rg/` = `data` (its `assets/`+`packs/`+`saves/`, minus the dev's `rg.dat` via SHIP_IGNORE) and `docks` (NOT `mypacks/`, raw `sounds/`, launchers, or lib) — placed next to `rg.exe` on Windows, into `Contents/Resources` on Mac. Windows also compiles `lt.nvgt` → bare `lt.exe` (lt.properties bundling off) dropped beside `rg.exe` (shares that folder's `lib/`) plus an **empty `mypacks/`** so authors have a workspace — this ships the level tool with the game, BGT-style. **Level tool is Windows-only for now** (its `run()`/`input_box` are Windows-oriented; a Mac tool would need a separate `lt.app` + a Mac run-level fix). Cleans stale `src/rg`/`src/rg.app` first (nvgt -c fails if a dir named after the script sits beside it; both are gitignored). Output → `releases/windows/RhythmRage_windows/rg/` and `releases/mac/RhythmRage_mac/rg.app`.
- **Package** → `releases/archives/`: Windows via `shutil.make_archive` (archive root = `rg/`). Mac via a hand-built `zipfile` that stamps **0755 on `rg.app/Contents/MacOS/rg`** (0644 elsewhere) so the cross-built app keeps its Unix exec bit — a naive Windows zip strips it and the `.app` won't launch. Extract → `rg/` (Windows) / `rg.app` (Mac).
